Status: accepted implementation handoff, explicitly human-confirmed on 2026-09-17.

Publication note (2026-09-18): this is the accepted M1 implementation contract. Original planning sources and prototype captures are preserved in [the frozen M1 planning archive](../archive/m1-planning/README.md); active rollback and deletion planning now uses [GitHub planning Maps](../planning/README.md). Destination is one nonblank Map property, not a Ticket or Dependency endpoint. A later graph projection must show it visibly; that does not introduce a renderer or Map-completion lifecycle into M1.

## 2. Values and runtime validation

All external inputs and typed public domain callers are subject to runtime checks. Type brands and readonly declarations do not validate JavaScript values or enforce authentication.

| Value | Required contract |
| --- | --- |
| MapId, TicketId, ClaimantId, ContentId, ActorId, ClientId | Complete match of `[A-Za-z0-9][A-Za-z0-9._:-]{0,127}`; 1–128 ASCII characters; case-sensitive; never trimmed or normalized; UUID syntax optional. |
| RevisionNumber | Positive JavaScript safe integer. Zero, negative, fractional, nonfinite, and unsafe numbers are invalid. Never reset/wrap on overflow. |
| Required human text | Nonblank string, retained without implicit trimming: title, Destination, question, statements, Decision rationale, content text, Reference locator, Provenance method, required reasons. |
| Notes | String; empty permitted. |
| Author | Caller-supplied valid ActorId, ClientId, and UTC RFC3339 occurredAt. No domain clock, randomness, or I/O. Revision number, not occurredAt, determines ordering. |
| Extensions | Namespaced keys completely matching `[a-z][a-z0-9_-]*\.[a-z][a-z0-9_.-]*`; finite, acyclic, plain JSON values. No coercion of unsupported values. No domain meaning assigned to their content. |
| Core objects | Unknown input fields rejected. Extensions are the supported extension location. Patch fields replace supplied values; no recursive merge. |
| References | Nonblank opaque locator; optional label. Do not fetch, resolve, or validate external reachability. |

IDs such as `constructor` and `toString` satisfy the grammar and must work as ordinary IDs; a dictionary implementation must not mistake inherited properties for stored Maps/Tickets. Ticket IDs are unique within their Map. Content IDs are unique across that Map's Fog and Scope Exclusions together. No globally unique Ticket/Content ID registry is required.

JSON-compatible input excludes cycles, nonfinite numbers, functions, symbols, and non-plain object values. JSON arrays/objects are recursively validated. Resulting facts use plain JSON shape; only Extensions impose the namespaced-key rule.

Creation requires id, title, Destination, author; optional notes/extensions default to empty. It prepares empty Tickets, Fog, and Scope Exclusions at Revision 1. It creates no readable empty shell or Revision 0. Null priorRevision means absence, not a stored revision number.

## 3. Domain and stored types

The command reference fixes the base value objects and command field names. Preserve these shapes:

```ts
declare const idBrand: unique symbol;
type Id<K extends string> = string & { readonly [idBrand]: K };
type MapId = Id<"Map">;
type TicketId = Id<"Ticket">;
type ClaimantId = Id<"Claimant">;
type ContentId = Id<"Content">;
type ActorId = Id<"Actor">;
type ClientId = Id<"Client">;
type RevisionNumber = number;
type JsonValue = null | boolean | number | string
  | readonly JsonValue[] | { readonly [key: string]: JsonValue };
type Extensions = Readonly<Record<string, JsonValue>>;
type NonEmpty<T> = readonly [T, ...T[]];
type TicketType = "grilling" | "prototype" | "research" | "task";
interface Reference { readonly locator: string; readonly label?: string }
interface Provenance {
  readonly method: string;
  readonly sources: readonly Reference[];
}
interface Evidence {
  readonly statement: string;
  readonly references: readonly Reference[];
  readonly provenance?: Provenance; // required when references is empty
  readonly extensions: Extensions;
}
interface Decision {
  readonly kind: "decision";
  readonly statement: string;
  readonly rationale: string;
}
interface Finding {
  readonly kind: "finding";
  readonly statement: string;
  readonly limitations?: string;
}
interface Completion {
  readonly kind: "completion";
  readonly statement: string;
  readonly resultingFacts?: Readonly<Record<string, JsonValue>>;
}
type OutcomeByType = {
  grilling: Decision; prototype: Decision;
  research: Finding; task: Completion;
};
interface Settlement<T extends TicketType> {
  readonly outcome: OutcomeByType[T];
  readonly evidence: readonly Evidence[];
  readonly references: readonly Reference[];
  readonly provenance: Provenance;
  readonly extensions: Extensions;
}
type StoredSettlement<T extends TicketType> = Settlement<T> & {
  readonly introducedAtRevision: RevisionNumber;
};
interface TicketBase<T extends TicketType> {
  readonly id: TicketId;
  readonly title: string;
  readonly question: string;
  readonly type: T;
  readonly prerequisites: readonly TicketId[];
  readonly extensions: Extensions;
}
type StoredTicket = {
  [T in TicketType]: TicketBase<T> & (
    | { readonly status: "open"; readonly claim: ClaimantId | null }
    | { readonly status: "settled"; readonly claim: null;
        readonly settlement: StoredSettlement<T> }
  )
}[TicketType];
interface MapContent {
  readonly id: ContentId;
  readonly text: string;
  readonly references: readonly Reference[];
}
interface StoredMapState {
  readonly id: MapId;
  readonly title: string;
  readonly destination: string;
  readonly notes: string;
  readonly fog: readonly MapContent[];
  readonly scopeExclusions: readonly MapContent[];
  readonly tickets: readonly StoredTicket[];
  readonly extensions: Extensions;
  readonly currentRevision: RevisionNumber;
}
interface MutationAuthor {
  readonly actorId: ActorId;
  readonly clientId: ClientId;
  readonly occurredAt: string;
}
```

`MapId` etc. are the distinct string brands in the command reference; the runtime grammar above is mandatory independently of branding. `RevisionNumber` is a number checked at runtime.

This reconciles the early `MapState`/`Ticket` reference with the later stored metadata contract. Actual current/prepared/historical states contain StoredTicket, including StoredSettlement. Settlement command input remains Settlement and must reject caller-supplied introducedAtRevision. A production `MapState` alias to StoredMapState is acceptable; publishing competing current-state types that lose introduction context is not.

Current state contains no Revision history collection, stored Frontier, independently mutable Decisions index, duplicated actor/client/time, Map lifecycle, owner/workspace, or tombstone. “Decisions so far” is a derived view of settled Tickets. Settlement, outcome, Evidence, Reference, and Claim have no independent M1 entity IDs.

## 4. Command contract

CreateMapInput, TicketInput, Access, and patches retain the command reference's shapes. CreateMapInput has id/title/destination/author and optional notes/extensions. TicketInput has id/title/question/type and optional extensions. Access has optional claimantId. MapPatch is a partial pick of title/destination/notes/extensions; TicketPatch is a partial pick of title/question/type/extensions. Empty patches are invalid.

ApplyRequest has mapId, expectedRevision, author, and nonempty ordered commands. It concerns exactly one Map. The union below preserves all accepted commands; Settlement is the input type, not StoredSettlement:

```ts
interface CreateMapInput {
  readonly id: MapId;
  readonly title: string;
  readonly destination: string;
  readonly notes?: string;
  readonly extensions?: Extensions;
  readonly author: MutationAuthor;
}
interface TicketInput {
  readonly id: TicketId;
  readonly title: string;
  readonly question: string;
  readonly type: TicketType;
  readonly extensions?: Extensions;
}
type Access = { readonly claimantId?: ClaimantId };
type TicketPatch = Readonly<Partial<
  Pick<TicketInput, "title" | "question" | "type" | "extensions">
>>;
type MapPatch = Readonly<Partial<
  Pick<StoredMapState, "title" | "destination" | "notes" | "extensions">
>>;
type SettleCommand = {
  [T in TicketType]: {
    readonly kind: "ticket.settle";
    readonly ticketId: TicketId;
    readonly ticketType: T;
    readonly claimantId: ClaimantId;
    readonly settlement: Settlement<T>;
  }
}[TicketType];
type Command =
  | { readonly kind: "map.update"; readonly patch: MapPatch }
  | { readonly kind: "ticket.create"; readonly ticket: TicketInput }
  | ({ readonly kind: "ticket.update"; readonly ticketId: TicketId;
       readonly patch: TicketPatch } & Access)
  | { readonly kind: "ticket.reopen"; readonly ticketId: TicketId;
      readonly reason: string }
  | SettleCommand
  | ({ readonly kind: "dependency.add" | "dependency.remove";
       readonly dependentId: TicketId; readonly prerequisiteId: TicketId } & Access)
  | { readonly kind: "claim.acquire";
      readonly ticketId: TicketId; readonly claimantId: ClaimantId }
  | { readonly kind: "claim.release";
      readonly ticketId: TicketId; readonly claimantId: ClaimantId; readonly reason?: string }
  | { readonly kind: "claim.clear"; readonly ticketId: TicketId;
      readonly expectedClaimantId: ClaimantId; readonly reason: string }
  | { readonly kind: "content.add" | "content.update";
      readonly section: "fog" | "scopeExclusions"; readonly item: MapContent }
  | { readonly kind: "content.remove"; readonly section: "fog" | "scopeExclusions";
      readonly itemId: ContentId };
interface ApplyRequest {
  readonly mapId: MapId;
  readonly expectedRevision: RevisionNumber;
  readonly author: MutationAuthor;
  readonly commands: NonEmpty<Command>;
}
```

| Command | Required behavior |
| --- | --- |
| map.update | Replace supplied fields, preserving one nonblank Destination. Empty notes allowed. |
| ticket.create | Unique immutable TicketId; open, unclaimed, no Settlement/prerequisites. Dependencies added separately. |
| ticket.update | Open only. Claimed Ticket requires matching Access claimantId; unclaimed open Ticket needs no Claim. Replace supplied fields. |
| ticket.reopen | Settled only, nonblank reason. Remove current Settlement; retain descriptive fields and Dependencies; leave open/unclaimed. No implicit downstream cascade. |
| ticket.settle | Open, currently claimed by supplied claimantId, all prerequisites settled at this command's position; actual Ticket type equals ticketType and outcome matches that type. Attach one stored Settlement with next Revision's introduction context and clear Claim atomically. |
| dependency.add | Both endpoints exist in this Map, no self/duplicate. Dependent open; claimed dependent requires matching Access claimantId. Prerequisite may be open or settled. |
| dependency.remove | Dependent open and access allowed; referenced edge must exist. No automatic removal on settlement. |
| claim.acquire | Ticket is in Frontier at this command's position. Repeated acquisition, even by same claimant, is rejected. |
| claim.release | Open Ticket with current Claim matching claimantId; release only that Claim. An optional reason, when present, is nonblank and recorded like a clear reason. |
| claim.clear | Current Claim matches expectedClaimantId, nonblank reason; expectedRevision still applies to whole request. Deliberate manual override, not M1 administrator authentication. |
| content.add | Caller ID unique across both content sections; add supplied item. |
| content.update | Item exists in selected section; replace supplied item without changing its identity. |
| content.remove | Item exists in selected section; remove it. This is content editing, not the deferred Ticket/Map deletion feature. |

Grilling/prototype settles with Decision; research with Finding; task with Completion. Decision requires rationale. Finding requires at least one Evidence or Reference. An accepted inconclusive Finding may describe checked scope/limitations and sources; unfinished work cannot be represented as an accepted Completion. M1 validates the structured result rather than claiming to verify factual truth or human acceptance outside its caller.

Evidence needs at least one Reference or explicit Provenance. Settlement always contains semantic Provenance. Mutation authorship/time comes from its introducing Revision, not extra Settlement fields. Store accepted compact results, not conversation transcripts or raw activity streams.

ClaimantId denotes a logical work session, not ActorId or ClientId. Independent concurrent sessions generate different IDs; continued logical work may reuse its ID. M1 has no session registry or authenticity check, lease/expiry, automatic takeover, independent ClaimId, or per-claimant quota. One claimant may reserve several eligible Tickets. Revision actor may differ from claimant.

Transfer is release + acquire by a different claimant in one batch, or clear + acquire if the old session is unavailable. Each command still obeys its gates. An acquire followed by release with otherwise unchanged content is a no-net-change rejection.

## 5. Pure preparation and invariant stages

Expose synchronous pure prepareCreate, prepareApply, calculateFrontier and runtime ID/input decoding. Preserve the command reference's outer result conventions, reconciling its prepared payload to PreparedCommit:

```ts
type Result<T, E> = { readonly kind: "ok"; readonly value: T }
  | { readonly kind: "error"; readonly error: E };
type PrepareResult =
  | { readonly kind: "prepared"; readonly change: PreparedCommit;
      readonly frontier: readonly TicketId[] }
  | { readonly kind: "rejected"; readonly rejection: Rejection }
  | { readonly kind: "conflict"; readonly conflict: Conflict };
declare function parseId<K extends string>(
  kind: K, input: unknown
): Result<Id<K>, InvalidInput>;
declare function decodeApplyRequest(raw: unknown): Result<ApplyRequest, InvalidInput>;
declare function prepareCreate(input: CreateMapInput): Result<PreparedCommit, InvalidInput>;
declare function prepareApply(current: StoredMapState, request: ApplyRequest): PrepareResult;
declare function calculateFrontier(current: StoredMapState): readonly TicketId[];
```

The declarations are specification signatures, not executable implementation. Raw input decoding and typed entry validation use the same constraints; successful decode does not waive semantic checks.

For apply:

1. Validate the complete request shape and every command payload before any command executes.
2. Check request mapId against supplied current state's id, and expectedRevision against its head. Identity mismatch is invalid input; stale revision is Conflict.
3. Execute commands in order on private state. Check existence, lifecycle, access, and operation-specific gates at each position. Claim acquire/settlement require satisfied prerequisites at that position.
4. Validate the complete final graph: same-Map endpoints, no dangling edges/cycles, every settled Ticket has settled prerequisites, and every claimed Ticket is open with settled prerequisites.
5. Reject no-net-change; otherwise advance once and derive Frontier. Reject unsafe overflow rather than producing a next revision.
6. Return prepared output, never durable success. Adapter commitment must perform a second authoritative comparison.

Graph final checks permit explicit reopening upstream before downstream within one atomic batch. A rejected command is not rescued by a later command. Whole-input validation precedes semantic execution, so an invalid late payload rejects without executing an otherwise valid earlier command.

Dependency means “dependent A requires prerequisite B,” with AND semantics and no conditional/OR groups. All referenced endpoints are local to the current Map; merely existing in another stored Map does not qualify. Reopening upstream with settled transitive downstream fails unless all affected settled downstream Tickets are explicitly reopened in the batch. Blocking a claimed Ticket fails unless the batch explicitly releases/clears that Claim. No silent cascade, Claim removal, or edge removal occurs.

No-net-change compares actual resulting domain content, not a manufactured new head number or operation authorship/summaries. Empty batches/patches, duplicate edges, missing removals, repeated claims, and artificial acquire/release cannot manufacture history. Reopening and subsequently settling again introduces a new accepted Settlement with new introducedAtRevision under the history contract, even when wording repeats an old result.

The accepted Answer Desk follow-on amends this check through its [agent request-closing contract](answer-desk.md#81-revision-boundary-and-adapters), subject to that slice's implementation and release boundary. The original M1 command set and acceptance evidence remain unchanged.

Frontier is exactly all open, unclaimed Tickets whose prerequisites are all settled; no prerequisites is vacuously eligible. Return ascending ASCII lexical TicketId, not locale order or priority. Compute it from selected state; never persist/mutate it as another source of truth.

## 6. Result and error contracts

```ts
interface InvalidInput {
  readonly code: "invalid_input";
  readonly path: readonly (string | number)[];
  readonly constraint: string;
}
type CommandErrorCode =
  | "ticket_not_found" | "ticket_already_exists"
  | "ticket_not_open" | "ticket_not_settled"
  | "ticket_already_claimed" | "claim_required" | "claim_mismatch"
  | "claim_not_found" | "unsettled_dependency"
  | "dependency_already_exists" | "dependency_not_found" | "self_dependency"
  | "settlement_type_mismatch" | "content_already_exists" | "content_not_found";
type InvariantErrorCode =
  | "dependency_cycle" | "dangling_dependency"
  | "settled_ticket_has_open_prerequisite"
  | "claimed_ticket_has_open_prerequisite";
type Rejection =
  | { readonly stage: "input"; readonly error: InvalidInput }
  | { readonly stage: "command"; readonly commandIndex: number;
      readonly code: CommandErrorCode; readonly ticketIds: readonly TicketId[] }
  | { readonly stage: "final_state"; readonly code: InvariantErrorCode;
      readonly ticketIds: readonly TicketId[] }
  | { readonly stage: "final_state"; readonly code: "no_changes" };
interface Conflict {
  readonly mapId: MapId;
  readonly expectedRevision: RevisionNumber;
  readonly currentRevision: RevisionNumber;
}
```

Input paths and commandIndex locate errors in the submitted object/array. Command index is the array position; it does not number committed Revisions. Tests assert applicable structured locations and stable codes, not constraint prose or translated message wording. The contract fixes stage order and command order; it does not fix a winner among multiple simultaneous final invariants or multiple malformed fields. Use focused cases to assert each specific error, and retain deterministic validation in implementation.

Missing/unmatched Claim is distinguished from already-claimed acquisition. A mismatched supplied session must not override the existing Claim merely because expectedRevision is fresh. Ordinarily rejected/conflicting requests return data, not thrown exceptions. Invalid identities, metadata, shape, and inability to advance a safe revision use invalid_input, not a successful partial preparation.

## 7. Prepared value, Revision, and storage port

Unify the early PreparedChange and later Adapter input into an internal opaque PreparedCommit. The preparation module alone mints it; external JSON state-import is not supported. Production callers cannot structurally construct it in ordinary type-checked code. This is type opacity, not authentication or protection from malicious in-process casts.

```ts
interface SemanticChange {
  readonly commandIndex: number;
  readonly command: Command["kind"] | "map.create";
  readonly subjectId: string;
  readonly reason?: string;
}
declare const preparedBrand: unique symbol; // internal, not a caller constructor
interface PreparedBase {
  readonly [preparedBrand]: true;
  readonly mapId: MapId;
  readonly next: StoredMapState;
  readonly author: MutationAuthor;
  readonly changes: NonEmpty<SemanticChange>;
}
type PreparedCommit = PreparedBase & (
  | { readonly kind: "create"; readonly priorRevision: null }
  | { readonly kind: "apply"; readonly priorRevision: RevisionNumber }
);
interface Revision {
  readonly mapId: MapId;
  readonly revision: RevisionNumber;
  readonly priorRevision: RevisionNumber | null;
  readonly kind: "create" | "apply";
  readonly author: MutationAuthor;
  readonly changes: NonEmpty<SemanticChange>;
  readonly state: StoredMapState;
}
type ReadResult<T> =
  | { readonly kind: "found"; readonly value: T }
  | { readonly kind: "not_found"; readonly code: "map_not_found"; readonly mapId: MapId }
  | { readonly kind: "not_found"; readonly code: "revision_not_found";
      readonly mapId: MapId; readonly revision: RevisionNumber }
  | { readonly kind: "rejected"; readonly error: InvalidInput };
type CommitResult =
  | { readonly kind: "committed"; readonly revision: Revision;
      readonly frontier: readonly TicketId[] }
  | { readonly kind: "conflict"; readonly conflict: Conflict }
  | { readonly kind: "rejected"; readonly code: "map_already_exists" | "map_not_found";
      readonly mapId: MapId };
interface StateAdapter {
  readCurrent(mapId: MapId): Promise<ReadResult<StoredMapState>>;
  readRevision(mapId: MapId, revision: RevisionNumber): Promise<ReadResult<Revision>>;
  commit(prepared: PreparedCommit): Promise<CommitResult>;
}
```

Create prepares kind=create, null prior, next.currentRevision=1. Apply prepares kind=apply, prior=current head, next.currentRevision=prior+1. mapId equals next.id. Adapter checks this envelope's identity/kind/prior/number coherence defensively, without replaying business commands. A malformed supposedly trusted internal envelope is a programming failure, not an additional public import rejection protocol; publish nothing.

Changes preserve command order, kinds, subjects, required reopen/clear reasons, and any supplied release reason. Creation records map.create. Full state is the authoritative historical content; summaries are not an event replay stream or chat transcript. M1 requires no history reconstruction by replay and no rendered semantic diff. Actual differences between two historical states come from comparing those states, not inferring them from summaries alone.

At settlement preparation derive introducedAtRevision from the batch's next revision, never from the caller. Preserve unchanged settled Tickets' introduction context through other Map changes. Reopen removes current Settlement; old snapshots retain it. Re-settle creates new introduction context even with repeated wording. Resolve original actor/client/time through the containing Map's introduction Revision. A historical read includes the Claims that actually existed then but does not reacquire them or change current state.

## 8. In-memory Adapter behavior

One fresh instance is empty and can store multiple distinct Maps, each with isolated current state/history and independent revision sequence from 1. Each request/prepared commit still concerns exactly one Map. There is no list/search, cross-Map batch/transaction, shared instance data, filesystem persistence, or restart loading.

Reads validate MapId and requested revision at runtime. Missing Map is map_not_found; a valid missing revision of an existing Map is revision_not_found. Invalid revision syntax/range is invalid_input, not absence. Wrong MapId never returns another Map's data. A single read is atomic; separate reads may span a commit. Pin an existing immutable revision for a stable historical view.

Commit captures prepared input immutably before asynchronous work can yield. At its publication point:

- Create atomically checks absence of that mapId. Existing same ID yields map_already_exists without overwrite; different ID may succeed in the same instance.
- Apply atomically checks that mapId exists and its stored head equals priorRevision. Absence yields map_not_found; mismatch yields Conflict with actual current head.
- Publish the new current state and immutable Revision together, or neither. Advance exactly once; preserve prior history. No intermediate commands, partial state, or orphan history may be observed.
- Return the exact Revision this operation committed and Frontier derived from its state, even if another operation subsequently advances the head. Do not form success by rereading latest state.

No asynchronous gap may allow two callers to pass a head check and then both publish against that head. A synchronous check/publication critical section is an available in-memory implementation choice; no externally exposed transaction handle is needed.

Unexpected infrastructure/programming failures reject the Promise instead of fabricating a domain rejection/conflict. A test-only internal seam may fail immediately before publication and must leave all stored Maps/current states/history unchanged. It is not a fourth public operation. This local guarantee does not promise known commit outcomes for a future remote/database failure.

Stored state/history and exposed values have no writable caller aliases. Apply must not mutate its supplied current state/request. Later mutation of original inputs, prepared data, read output, or commit output must not change stored content/history. Defensive copies or freezing are valid; attempted frozen mutation may throw. This isolation extends into extensions, resulting facts, Reference arrays, and Settlement/author/summary objects.

No automatic merge, rebase, retry, or idempotency-key cache exists. Replay of an already committed apply against its old head conflicts; replay of create encounters duplicate MapId. The caller rereads and decides whether its intention is already satisfied or requires a new request.

## 9. Mandatory acceptance cases and traceability

The accepted family matrix is expanded below into concrete case IDs. IDs group parameterized scenarios; each listed branch/error must have an executable assertion. Use public seams and the real memory Adapter, not private storage inspection or a fake storage implementation. Black-box checks may enumerate known revision numbers with readRevision; no list/history API is added for tests.

For any rejection/conflict/pre-publication failure, compare the complete affected current state and every previously known historical record before/after, verify the proposed next revision is absent, and verify unrelated Maps remain unchanged. This rule applies to all negative cases below, not just one atomicity test.

## 10. Completion gate and implementation handoff

M1 is complete only when strict TypeScript checking and every mandatory scenario above pass, with each normative rule traceable to an executable assertion. Parameterized cases must exercise every listed branch; the table is not satisfied by one happy-path test per row. No arbitrary coverage percentage or UI screenshot substitutes for these checks.

Suggested reversible implementation sequence:

1. Configure strict ESM TypeScript/Vitest; implement runtime values and correlated state/input types.
2. Implement pure create/apply, ordered gates, final graph validation, canonical Frontier, no-op handling, and stored introduction metadata.
3. Implement opaque preparation output and real multi-Map memory Adapter with atomic publication, detached values, full immutable history, and test-only pre-publication failure seam.
4. Add public-seam cases, bounded enumeration, race/failure/isolation checks, type fixtures, and vertical workflows; run all gates and report actual results.

Do not copy prototype logic wholesale: demos omit substantial validation and some commands/types. The command prototype's captured types predate StoredSettlement; the Adapter capture's single-Map limitation was withdrawn. Consult the corrected working references and this reconciliation, not the outdated occupancy rule.

No known implementation-blocking domain choice remains after synthesis. Error prose, same-stage multi-error precedence, helper names/layout, internal graph traversal, and copying/freezing mechanism may be chosen consistently during implementation. If a genuine conflict with a confirmed contract is discovered, stop that decision branch and bring it to the human; do not silently change scope or weaken acceptance.

This handoff does not authorize production implementation by itself. The current planning session has not installed dependencies, type-checked production code, run the M1 suite, or verified prototype UI clicks. Prototype syntax/pure-model checks are historical evidence of design exploration only.

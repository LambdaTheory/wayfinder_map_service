# Wayfinder Map Service v1

Status: accepted product specification

## Outcome

Provide one persistent decision map that can be created in ChatGPT, continued in Codex, inspected in a browser, and used by another MCP-capable client without translating state by hand.

The system adapts Matt Pocock's Grilling and Wayfinder methods while adding bounded convergence, durable state, revision history, visual inspection, portable export, and failure recovery.

## Success scenario

One real project completes this end-to-end path:

1. The user explicitly invokes `@wayfinder` in ChatGPT desktop and creates a map.
2. A later ChatGPT conversation resumes that map from the remote service.
3. An attached `@grilling` session settles one decision ticket and writes the result back.
4. Codex reads the same current revision and advances another ticket.
5. The user opens a visual map, inspects a semantic revision diff, and rolls back one change.
6. The user creates and revokes a read-only share link.
7. The user exports versioned JSON and readable Markdown.
8. A simulated outage produces a recovery bundle that can later be reviewed and imported.

## Scope

### Included in v1

- Explicit `@grilling` and `@wayfinder` entry points.
- A remote, client-neutral MCP server as the authoritative state owner.
- A Wayfinder-specific domain model with extension fields.
- Single-user operation with explicit `owner` and `workspace` ownership fields.
- Revisioned mutations, semantic diffs, export, and recovery import.
- A private web renderer with zoom, filtering, and node details.
- Revocable read-only share links.
- OAuth for interactive clients and separate credentials for trusted machine clients.
- Deployment on the user's personal Dokploy host with PostgreSQL and encrypted S3 backups.

### Deferred beyond v1

- Collaborative editing and invitations.
- A general-purpose graph database interface.
- Direct editing inside the graph renderer.
- Full transcript storage.
- Silent offline replay and automatic merge.
- Universal-directory publication and complete Web/mobile validation.
- Kubernetes deployment, high availability, billing, and quotas.

## Product behavior

### Grilling

- Invocation is explicit.
- A standalone session remains temporary until the user chooses to save it.
- A session started with a map and decision ticket writes accepted decisions to that map.
- The assistant asks every currently available frontier question in a round and gives a recommended answer for each.
- Facts are researched by the agent; choices remain with the user.
- Standard mode performs a convergence checkpoint after three rounds or fifteen questions.
- Quick, standard, and exhaustive depth modes may override the checkpoint cadence.
- A checkpoint reports settled decisions, remaining frontier, repetition risk, and the estimated value of continuing.

### Wayfinder

- Invocation is explicit.
- Every map has exactly one destination.
- The current frontier is derived from unresolved tickets, settled dependencies, and active claims.
- Read-only research may run without additional approval.
- Interviews, prototypes, external writes, destructive changes, and bulk rewrites require risk-appropriate confirmation.
- Each accepted decision or ticket-state change produces one atomic revision.
- Chat history provides process context; the remote map remains authoritative.

## Domain invariants

- A map has one owner and one current revision.
- A map has exactly one destination after initialization.
- Every decision ticket has one status and zero or more dependencies.
- A ticket enters the frontier only when it remains unresolved and every dependency is settled.
- A successful mutation supplies the expected prior revision, applies atomically, increments the revision, and records a semantic summary.
- A stale mutation returns a conflict containing the current revision. The rejected request is void: the client re-reads, reports the new Revision and stops until the human issues a new request after seeing that Revision.
- Existing revision history remains immutable.
- Structured decisions, evidence, references, and provenance are stored. Full conversation transcripts are excluded by default.
- Share links grant read-only access and can be revoked independently of the map.
- Permanent deletion removes the map, revisions, recovery material held by the service, and share credentials.

## Module design

The external seam is one small MCP interface. It hides storage, revisions, conflict detection, authorization, rendering, and audit behavior behind a few high-leverage operations.

Candidate operations for the first interface design:

- `map_open`: create a map or resume an existing map by stable handle.
- `map_apply`: validate and atomically apply one or more semantic commands against an expected revision.
- `map_render`: return structured data, an MCP Apps UI resource when supported, and a browser URL fallback.
- `map_export`: produce canonical JSON plus derived Markdown and SVG/HTML artifacts.
- `map_share`: create, inspect, or revoke a read-only share capability.

Exact input schemas remain an implementation design task. The interface must avoid exposing SQL records, renderer internals, or client-specific conversation formats.

Internal seams become real only when two adapters exist. v1 requires these adapters:

- State storage: an in-memory adapter for tests and a PostgreSQL adapter for production.
- Rendering: structured headless output and a web/MCP Apps UI projection.
- Identity: OAuth authorization code with PKCE for interactive clients and PAT or client credentials for trusted machine clients.

## Security and privacy

- Interactive ChatGPT access uses OAuth authorization code with PKCE.
- Trusted CLI and agent clients receive separate PAT or client-credential identities.
- Initial scopes are `read`, `write`, and `admin`.
- Every client identity can be revoked independently.
- Logs record request identifiers, operation names, timing, actor, and parameter summaries. Decision text and evidence bodies stay out of logs.
- Maps are private by default.
- Anonymous access is limited to explicit, revocable read-only share links.
- Normal deletion starts a 30-day recovery period. Explicit permanent deletion erases active state immediately.

## Portability and failure behavior

- Versioned JSON is the canonical exchange format.
- Markdown is the human-readable and agent-readable snapshot format.
- SVG/HTML are derived presentation formats.
- Clients that cannot render MCP Apps UI receive structured output and a normal browser URL.
- During service failure, clients continue only in explicit offline mode and produce a recovery bundle.
- Importing a recovery bundle requires a user-visible review and an expected-revision check.

## Deployment target

- Development: mba-m4 with a temporary Cloudflare Tunnel for end-to-end connection testing.
- Production: `wayfinder.flashflock.com` on the personal Dokploy host behind Traefik and TLS.
- Runtime: one application process exposing MCP, OAuth, JSON endpoints, and the renderer, backed by PostgreSQL.
- Backups: encrypted S3 backup every day, retained for 30 days, with one recovery exercise during the first month.
- NAS may receive a secondary backup or read-only archive later.
- GBrain provides a reference implementation for OAuth and remote MCP security patterns; Wayfinder keeps independent product and domain code.

## Delivery slices

### Local post-M1 MCP/SQLite acceptance slice

The human-confirmed [Codex MCP and SQLite acceptance planning Map](https://github.com/kun-g/wayfinder_map_service/issues/27) selects an independent loopback MCP service, SQLite and Codex-first real acceptance as a bounded local slice. Its [implementation handoff](mcp-sqlite.md) was explicitly human-confirmed on 2026-09-18. SQLite replaces the PostgreSQL requirement for this slice only, not the wider production persistence/deployment direction below. It does not complete M2–M6, introduce OAuth/rendering/sharing/export/recovery import, or migrate existing rollback/deletion Maps. The original operation names above are candidates; this slice's confirmed four-tool interface takes precedence for its implementation.

New exploration Maps adopt product MCP authority only after implementation and explicit live human acceptance; GitHub retains implementation Issues/PRs and bootstrap planning. Until then no Wayfinder service availability is asserted. The local slice pauses authoritative advancement on service failure; it does not implement the later offline Recovery Bundle path.

### Post-adoption self-contained MCP workflow slice

The human-confirmed product Map **Wayfinder MCP self-contained workflow** (`Wayfinder.McpSelfContained`) adds a later local slice without changing the delivered Map domain, SQLite storage contract or four-tool business interface. A compatible client receives enough server-supplied initialization instructions and locally sufficient tool metadata to create, resume, Claim and advance an exploration Map without reading repository files or installing a Wayfinder Skill. The complete workflow is also published as an MCP Resource and a side-effect-free MCP Prompt may provide an optional entry point; neither is a correctness dependency.

The workflow contract has its own SemVer, is generated deterministically from the repository's authoritative workflow Markdown and remains immutable for one service process. Its initial test publication is `1.0.0`; later compatible guidance uses ordinary SemVer without changing Map Revisions. This slice adds focused build/protocol tests and one isolated real ChatGPT/Codex journey with an explicit human acceptance gate. It does not add a fifth business tool, change Map tool schemas, deliver general plugin packaging, OAuth, production deployment or any other M2–M6 capability.

### Local read-only Map viewer slice

The live user accepted the [local read-only Map viewer requirements](map-viewer.md) on 2026-10-23. A browser page served by the local MCP service draws one Map's route, Destination, Fog and Scope Exclusions and follows new Revisions. It delivers part of M4 locally without changing the Map domain, storage contract or mutation interface. It excludes MCP Apps, editing in the renderer, sharing, public access and OAuth.

## Principal risks

- ChatGPT plugin availability and cross-surface behavior vary by account and workspace policy.
- Model-driven tool selection can drift from the workflow contract without focused evaluations.
- Renderer work can expand into a full editor before the decision workflow is proven.
- OAuth and share links expose sensitive personal decision data if scopes, logging, or revocation are incomplete.
- A single Dokploy host creates a shared failure domain; v1 accepts recovery measured in hours.
- Matt's upstream skills may change semantics; updates require provenance review and selective merging.

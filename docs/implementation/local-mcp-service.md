## Operator entry point

Pinned Node **26.3.0** is required. Build with `npm run build`; `src/mcp-service.ts` exports `startLocalMcpService(configuration)` returning an idempotent async `stop()`. The independent foreground command is:

```sh
npm run --silent start
```

The command reads operator environment configuration, never caller-selected paths or authors. Use `--silent` and environment variables, not credential/private-path command arguments; console output contains fixed safe lifecycle messages and metadata gap counters. Supply configuration privately in the operator's shell/process environment; do not commit it or include it in reports/Map content. No live token is provided here.

| Variable | Requirement |
| --- | --- |
| `WAYFINDER_DATABASE_PATH` | Canonical absolute private local existing DB outside repositories/worktrees/temp; inherited storage path/ownership/mode/symlink policy applies |
| `WAYFINDER_PORT` | Explicit decimal integer 1–65535, no whitespace/zero/fraction/automatic substitution |
| `WAYFINDER_TOKEN` | Required 32–256 characters in `[A-Za-z0-9._~-]`; operator should generate a high-entropy random value (e.g. 32 random bytes encoded as hex) |
| `WAYFINDER_ACTOR_ID` | Valid M1 Actor ID, captured from operator configuration |
| `WAYFINDER_CLIENT_ID` | Valid M1 Client ID, captured from operator configuration |
| `WAYFINDER_ALLOWED_ORIGINS` | Optional JSON array, default `[]`; each entry must be an exact canonical HTTP/HTTPS origin with hostname `127.0.0.1` or `localhost`, no path/credentials/wildcard |
| `WAYFINDER_CREDENTIALS_FILE` | Optional absolute path to an operator-written credentials file; see below |

Explicit first-use initialization remains the separate `initializeSQLite(path)` API from `src/sqlite-storage.ts` (built `dist/sqlite-storage.js`), at a nonexistent fresh private target only. The service never initializes, repairs, migrates, resets or substitutes storage. Missing/wrong/unsupported storage and ordinary open failures produce safe `storage_not_ready` startup failure before listening. Invalid configuration produces `invalid_configuration`; bind/occupied-port failures produce `port_unavailable`. Exit is nonzero, with no private path, raw cause or token. An occupied port is never replaced with a random one.

### Further credentials

`WAYFINDER_TOKEN` authors as `WAYFINDER_CLIENT_ID`. An operator who runs several clients against one service, such as the dedicated Wayfinder agents and the ChatGPT test relay, gives each its own token in the credentials file so that each Revision records which one wrote it:

```json
{ "credentials": [ { "clientId": "Codex:gpt-6-astra:xhigh", "tokenSha256": "<64 lowercase hex: SHA-256 of the raw token>" } ] }
```

An entry may add `"toolsOnly": true` for a client that shows its model the tool definitions but never the server instructions, as ChatGPT does. Sessions opened with that token get write tools whose `version` parameter states the release (compatibility mode, [Open conversations across an upgrade](client-upgrade.md)); `wayfinder chatgpt` sets it. The ChatGPT runner's own service sets the same for its primary token.

The service re-reads the file whenever a request presents a token other than `WAYFINDER_TOKEN`, so adding an entry admits that token on the next request and removing one revokes it there. A missing file, invalid JSON, an unknown field, an invalid Client ID or a malformed hash admits no file credential at all; `WAYFINDER_TOKEN` keeps working. The file holds only hashes; the launcher that writes it keeps it private (0600). A session authors with the Client ID of the credential that initialized it, and a later request in that session with any other credential is refused with 403. Authorship stays operator-configured as the [handoff](../spec/mcp-sqlite.md) section 6 requires; clients cannot name their own Client ID.

Every MCP request must use `/mcp`, exact Host `127.0.0.1:<configured-port>` and `Authorization: Bearer <operator-token>`. Since the [read-only Map viewer](map-viewer.md), other paths with the exact Host go to that viewer before the token check. A valid token with absent Origin is allowed. A present Origin must exactly match the explicitly configured local allowlist; arbitrary websites, `null`, trailing paths and unlisted local origins are forbidden. There is no CORS wildcard or public listener. Authentication is checked for POST/GET/DELETE, not just initialization. Revision author/time fields remain server-derived and unknown/system fields are rejected by the unchanged M1/tool validation.

The pinned SDK provides stateful Streamable HTTP sessions and JSON POST responses. GET responds 405 (no standalone server-initiated SSE/subscriptions); DELETE drains its session's admitted responses before closing that session. Both are permitted by the [MCP Streamable HTTP transport specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). No legacy SSE endpoint, STDIO bridge, event store/replay, compatibility text or automatic launch is added. Sessions share one synchronous real SQLite connection. Session deletion/conversation close does not close storage, stop the process, add a Revision or release/expire/take over logical Claims.

Exactly five tools retain once-only `structuredContent` and their input/output shapes. Service admission refusals extend only the safe infrastructure code enum with `service_busy`/`service_stopping`, `outcome: not_published`, `requiresRestart: false`, empty content and `isError: true`. No new domain result/error or pure M1 limit is introduced. Concurrency is counted around actual handler completion, not receipt delivery; abandoned/disconnected work retains its slot until it finishes. A fifth active tool call is explicitly refused, never queued or automatically retried. Operators/clients must not blindly retry a write after a missing receipt.

Request-body byte limit is **1,048,576 inclusive** before JSON decoding, including unknown/padding fields and UTF-8 bytes. Declared and streamed/chunked excess gets explicit HTTP 413 without parsing or publication; excess bytes are discarded without accumulating them or resetting an uploading socket before the refusal is consumable. Malformed UTF-8/JSON and protocol batches are rejected. The existing tool boundary enforces **100 commands inclusive**, not pure M1. Headers retain Node's ordinary HTTP parser bounds; the body cap is not an end-to-end latency or memory-budget guarantee.

SIGINT/SIGTERM calls `stop()`: synchronously stops admission (new requests 503), completes admitted work even after disconnect, closes SDK sessions/listener and then storage. Conversation lifetime is independent of process lifetime. Forced termination or transport loss leaves receipt outcome **unknown** until authoritative current/known-history reread. No automatic retry, merge, replay, Claim takeover or memory/GitHub/offline fallback. Safe storage errors preserve busy/non-publication/unknown/restart diagnostics; unusable storage refuses all later operations until explicit process/storage restart. Protocol errors retain their numeric code but discard SDK diagnostic prose/data; exception text, causes/stacks, SQL and request bodies are not logged.

## Default call metadata

Every local service entry appends private JSONL observations to `<databasePath>.calls.jsonl`, including the standalone command, the dedicated launcher and an isolated test service. This is outside the SQLite transaction and does not change a Revision or MCP response. Files must be owner-only (0600), regular and single-link; symlinks and unsafe existing files are refused without changing their permissions. No configuration flag is required. The read-only viewer is outside this MCP call log.

Records use `wayfinder-service-call/1`: `startedAt`, `durationMs`, `clientId`, `credentialFingerprint` (a domain-separated digest derived from the existing credential verifier, never the token or verifier), `mcpSessionId`, `presentedMcpSessionId`, `requestId`, `requestIdType`, `requestIdHash`, `httpMethod`, `httpStatus`, `method`, `tool`, `mapId` and `result`. B01's `SessionRecord.mcpSessionIds` joins `mcpSessionId`; a tool event's string `requestId` joins the JSON-RPC request ID converted to a string. Pair these keys: request IDs alone repeat across sessions. `requestIdType` distinguishes a numeric ID from a string ID with the same spelling. Unsafe string IDs retain only `requestIdHash = SHA-256("wayfinder-call-request/1" + NUL + id)`, which B08 can derive from B01's original string. A pattern-safe presented session ID remains in `presentedMcpSessionId` even when a restart makes the session unknown; `mcpSessionId` names a matched live session. HTTP status is null when no response could be completed. Client IDs keep the existing authorship format; the fingerprint distinguishes simultaneous launches of the same Combination. The fingerprint is `SHA-256("wayfinder-call-credential/1" + NUL + tokenSha256)`, where `tokenSha256` is the lowercase hex verifier from the existing credential registration. It is correlation evidence, never proof of human authorization.

Tool result classes match B01 (`read`, `committed`, `version-mismatch`, `conflict`, `input-error`, `command-rejected`, `map-exists`, `not-found`, `service-failure`, `transport-failure`). The SDK's expected GET 405 stream probe uses `stream-not-supported`, with HTTP method/status and session correlation; it is not a transport failure. Other successful protocol requests use `ok`. SDK/protocol and authentication failures are recorded too; fields unavailable before authentication/parsing are null. Free-form or malformed IDs, unknown tool names and private paths are not copied; unsafe request IDs are hashed. Only bounded ID fields and allowlisted method/tool/result names are recorded; arguments, results, prompts, rules, clientInfo prose, exceptions, SQL and raw credentials are excluded. Tool completion is recorded even when its client disconnected before receiving the result.

`serviceStartedAt` and monotonic `sequence` identify a process's observation order. Any failed observation or append increments `missingObservations`, immediately appends a safe `wayfinder-service-call-gap/1` counter to the independent private `<databasePath>.calls.gaps.jsonl`, emits the same counter to stderr, and leaves the business result unchanged. Context lookup and result classification are protected too; metadata retains no raw credential and never replays a business call. Subsequent successful records retain the cumulative count. Embedded operators can also read `service.metadataStatus()`; it returns observation and missing-observation counts without content. Graceful stop appends a `wayfinder-service-call-summary/1` record with `observations` and `missingObservations`; if the call file stays unwritable, the summary goes to the gap file and stderr. Gap records survive restart even when no later call succeeds. If both files and stderr fail, only the in-memory counter remains; no implementation can persist through total sink failure. Readers must treat malformed/truncated lines as gaps. Call, gap and launcher logs append across restarts, have no automatic rotation or size bound, and keep growing. An operator may stop the service they manage, archive its logs privately and restart to create new private files; logs are not a Map backup. Through the ChatGPT tunnel, the relay adds its configured token to public traffic, so those requests are recorded as authenticated calls of that credential, not as verified human requests. Unauthenticated calls are still recorded individually to preserve the R7 call inventory; counting them only in memory would lose that evidence.

Before Host and credential checks pass, observations contain only allowlisted HTTP method/status, timing and counters; client/session identifiers, fingerprints and parsed request fields stay null. In particular, `presentedMcpSessionId` is captured only after authentication, so a rejected request cannot persist arbitrary header content. Host, Origin and other raw header values are never recorded.

See [B07 implementation and verification](service-call-metadata.md) for the launcher join, tests and disposable service evidence.

## Answer Desk in 4.0.0

Answer Desk is on by default and has no disabled runtime surface. Omitted `answerDeskEnabled` / `WAYFINDER_ANSWER_DESK_ENABLED` and legacy `true` use the same five tools; explicit `false` refuses startup with `answer_desk_required`. This protects used databases and avoids instructions that demand unavailable commands. The viewer stays unkeyed/read-only until the launcher supplies its independent browser key.

The first startup of the everyday database on 3.2.0 or later (including 4.0.0) migrates format 1 to format 2 after a private consistent backup. This is one-way; the backup is retained and there is no downgrade. No everyday-service upgrade was performed for this change.

# Domain docs

This repository has one domain context.

- Read `GLOSSARY.md` before changing domain behavior or terminology.
- Read relevant files in `docs/adr/` before changing architecture or product semantics.
- Keep `GLOSSARY.md` as a glossary of domain-specific terms. Product requirements belong in `docs/spec/`; implementation state belongs in the local tracker.
- Use `.agents/skills/domain-modeling/GLOSSARY-FORMAT.md` when adding or sharpening a term.
- Use `.agents/skills/domain-modeling/ADR-FORMAT.md` when a hard-to-reverse, surprising trade-off with real alternatives has been settled.
- Point out genuine conflicts between code, specification, glossary, and ADRs before choosing one silently.
